# Caifubao Project Operations

This file contains commands and operational conventions. Repository-wide agent
policy is defined only in [`RULES.md`](./RULES.md); workflow and role routing are
in [`AGENTS.md`](./AGENTS.md).

## Project layout

| Path        | Purpose                                             |
| ----------- | --------------------------------------------------- |
| `backend/`  | Python 3.12 Flask API                               |
| `datahub/`  | Data collection, factors, scoring, and data quality |
| `frontend/` | Vue 3 / TypeScript application                      |
| `k8s/`      | Public Kubernetes examples                          |
| `openspec/` | Contract ledger and active changes                  |

## Local development

```bash
# Backend (default port 8000)
cd backend
source venv312/bin/activate
python main.py

# Frontend (default Vite port 5173)
cd frontend
npm run dev
```

Use `./scripts/caifubao` for health checks, data sync, scoring, backup, and
restore. See [`docs/operations/agent-cli.md`](./docs/operations/agent-cli.md).

## Validation

Use the minimum checks selected by [`RULES.md`](./RULES.md#validation). Common
commands:

```bash
# Use RUFF_VERSION from .github/workflows/ci.yml
ruff --version

# Backend
ruff check <paths>
ruff format --check <paths>
backend/venv312/bin/python -m pytest <focused-tests>

# Datahub
ruff check <paths>
ruff format --check <paths>
datahub/.venv/bin/python -m pytest <focused-tests>

# Frontend
cd frontend && npm run lint && npm run build

# OpenSpec
openspec validate --all --strict
```

## OpenSpec

Run the [spec gate](./RULES.md#spec-gate) before creating a change. The MVP
contract ledger is archived at `openspec/archive/mvp-quant-demo/`.

```bash
openspec status --change "<name>" --json
openspec instructions apply --change "<name>" --json
openspec validate --all --strict
```

Active changes live at `openspec/changes/<change-name>/` and normally contain a
proposal, specs, design notes when needed, and executable tasks. Keep each
change focused and archive it after completion.

## Git and PR workflow

Follow [`RULES.md`](./RULES.md#branch-and-pr). The default target is `develop`;
hotfixes may target `main` when explicitly required.

```bash
git fetch origin develop --quiet
git switch -c <type>/<short-name> origin/develop

# Before handoff
git fetch origin develop --quiet
git merge-tree $(git merge-base HEAD origin/develop) origin/develop HEAD

# When PR delivery is in scope
gh pr create --draft --base develop
gh pr checks <PR_NUMBER> --watch
gh pr ready <PR_NUMBER>
```

Use Conventional Commits and squash merge unless a maintainer requests a
different strategy. Never force-push shared branches or bypass failing CI.

## Containers and deployment examples

```bash
docker build -t caifubao-backend backend
cd frontend && npm run build
kubectl kustomize k8s/overlays/example-development
```

Only public example configuration belongs in this repository. Real deployment
commands and overlays belong in `caifubao-private`.
