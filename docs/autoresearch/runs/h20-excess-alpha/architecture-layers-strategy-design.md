# 数据 → 因子 → 信号 → 评分 → 策略：分层关系与策略层设计

> 总体架构说明（2026-09）。回答：行情/因子/信号/评分/策略之间是什么关系，策略层应当
> 如何实现。结合本仓库现状（datahub 生产链 + backend 展示/回测 + autoresearch 研究链）
> 与 H20 研究结论（8 分量恒反向、flip_wide 构造层翻转、估值因子正 IC）给出设计建议。

## 一、现状分层（代码实际存在什么）

```
┌─ 数据层（datahub）───────────────────────────────────────────────┐
│ stock_daily_quote     行情（OHLCV + 估值占位 + trade_status）      │
│ stock_daily_basic     ★新★ tushare 估值（pe_ttm/pb/ps/dv/市值/换手）│
│ stock_industry        行业分类（SW L1）                            │
│ finance_market        市场/交易日历                                │
├─ 因子层（datahub factor_runner / tech_factor_runner）─────────────┤
│ FQ_FACTOR（前复权因子） MA_10/20/30/60/120 → stock_factor_daily   │
│ （估值/质量尚非"因子"——只有原始字段，无构造产物）                   │
├─ 信号层（signal_runner）──────────────────────────────────────────┤
│ 均线交叉等规则信号（HFQ_PRICE_UPCROSS_MA_60 …）→ stock_signal_daily│
├─ 评分层（scoring_runner / scoring_engine）────────────────────────┤
│ 8 分量：signal_strength/momentum/trend/breakout/industry_momentum/ │
│        relative_strength/real_relative_strength/risk_penalty       │
│ 逐股算分量 → 截面 rank → Σ(rank×weight) → 0-100 → stock_score_pred │
│ （研究链：autoresearch 用同一分量做 H20 候选评估）                  │
├─ 策略层（datahub backtest_runner + backend strategy）─────────────┤
│ datahub：SCORE_THRESHOLD/MA_CROSS 等回测（评分驱动、单股/对比）    │
│ backend：StrategyDirecter/registry + Portfolio/Position/Transaction│
└───────────────────────────────────────────────────────────────────┘
```

当前**关系实质上是单向流水线**：行情 → 因子 → 信号 → 评分 → 策略(回测)，每层消费上一层
的产物、写入自己的集合。**没有"策略"作为一等对象在生产链中运行**——评分驱动回测
（SCORE_THRESHOLD，datahub 侧）与展示型策略/组合（backend 侧）都是验证/演示工具，生产侧
只有评分，评分的最终用途（买什么/不买什么）未在生产代码里闭环。

## 二、五层之间是什么关系（本质）

每一层都是**对上一层的压缩/解释**，且每层都有一个核心语义问题：

| 层 | 输入 | 输出 | 核心语义（本层在回答什么） | 可检验性 |
|---|---|---|---|---|
| 行情 | 交易所 | 逐日 OHLCV/估值 | 发生了什么 | 事实（无对错） |
| 因子 | 行情 | 每股每日一个数值 | 把价格历史**压成一个特征**（涨了多少/贵不贵） | 单因子 IC |
| 信号 | 因子(+规则) | 事件/布尔 | 特征**何时触发行动**（上穿/突破） | 信号命中后收益 |
| 评分 | 多因子/信号 | 每股 0-100 横截面序 | 谁**相对**更值得买（多因子加权 → 一维序） | 分数分位 → 前向收益 |
| 策略 | 评分+约束 | 组合/调仓指令 | **买什么、买多少、何时换**（含风险/成本/仓位约束） | 组合 IR/回撤/换手 |

关键：**评分是截面排序，策略是投资组合决策**。评分回答"哪些股票分数高"，策略回答"在高分
股票里，用多少仓位、什么节奏、承担什么风险去构建一个组合"。二者之间还隔着：
- 选择函数（top-N？阈值？分位？）
- 风险/约束（单票上限、行业暴露、流动性下限、是否排除 ST/BSE）
- 交易执行（T+1、滑点/佣金/印花税、涨跌停阻塞、最小交易单位）
- 组合再平衡（固定周期？分数漂移触发？）

H20 研究揭示的教训就在评分→策略之间：
- 评分**方向反了**（8 分量恒反向）→ 任何策略拿"高分=买"都会系统性亏；
- 修正应在**构造层**（flip_wide）而非策略层（不是"买低分"这种 usage 反转）——策略层始终
  应是"分数越高越优先"，方向问题交给评分构造层解决，语义才能保持干净可审计；
- **选股宽度**（top5%/30 只 vs top20%/800 只）在策略层是决定性参数——评分给出序，策略
  决定切多薄，30 只窄书把有效信号切成了噪声。

## 三、缺口分析（现状 vs 应有）

1. **因子层与估值数据脱节**：stock_daily_basic 有 pe_ttm/pb/市值/换手，但没有任何 runner
   把它们转成因子产物（如 1/pe、size 中性化后的值）进 factor 集合或快照。研究链里它们是
   临时 join，生产链里不存在。
2. **评分层只有一组固定方向的分量**：components.py 的 8 分量方向在代码里写死（含
   risk_penalty 作为 penalty 减项），没有"按模型版本/候选配置声明方向+权重"的机制——
   autoresearch 的 candidate.yaml 表达了方向/权重/selection，但那是**研究侧**的配置，生产
   scoring 不吃它。
3. **评分与策略之间的"选择/组合/执行"没有生产实现**：SCORE_THRESHOLD 回测是验证工具，
   不是每日实盘组合生成器。没有"每天收盘后：跑评分 → 按策略配置选股 → 输出今日目标
   组合/调仓清单"的产物。
4. **信号层产物被评分引擎消费但信号列表贫瘠**：signal_strength_component 会读取当日
   signals（scoring_service `_get_signals_on_date`），但生产信号列表基本只有均线交叉类——
   信号层是评分的一个输入通道，远未用满。
5. **回测与研究快照是两套**：backtest_runner（backend 策略回测）与 autoresearch
   snapshot（T+1 执行回测）并行存在，评价口径不一致（friction/基准/换手）——策略层设计
   必须先统一"用什么口径验证策略"。

## 四、策略层应当如何实现（设计建议）

### 4.1 定位：一个"评分 → 组合"的可配置产物层

```
scoring_runner（每日，生产）
   └→ stock_score_prediction（每股 0-100，已有）
        └→ strategy_runner（每日，生产，新增）
             读评分 + 策略配置（candidate 语义下沉到生产）
             输出 strategy_position / strategy_order（目标组合与调仓）
                   └→ （可选）对接 portfolio/交易执行
```

策略配置 = autoresearch candidate 语义的**生产版**：方向/权重 + selection + 约束，存为
versioned 配置（model_version 已有先例）。同一个候选可同时被研究链评估和在生产链执行，
保证"研究的=跑生产的"。

### 4.2 策略原语（需要明确的四个决策）

| 决策 | 选项 | 备注 |
|---|---|---|
| 排序源 | 生产评分（0-100） | 语义：分数越高越优先（选高买入，方向问题在构造层解决） |
| 选择函数 | top-N / 分位阈值 / 分数阈值 | H20：宽书（top 20% 或排除底部）优于 30 只窄书 |
| 约束 | 单票 max pct、行业上限、流动性下限、ST/BSE/停牌排除 | 快照里已有 eligibility 语义，需下沉 |
| 再平衡 | 固定周期（如每周） vs 分数漂移触发 | 换手与成本由再平衡频率决定 |

### 4.3 与五层的关系规则（写进实现的原则）

1. **方向只发生在构造层，策略层永远是"选高"**：策略不要实现"买低分"逻辑；评分方向错误
   时改评分的分量方向/权重（version bump），不改策略语义。保证任何策略的基准测试都有意义。
2. **估值/市值因子先进因子层**：把 stock_daily_basic 的 EP/BP/市值/换手做成正式因子产物
   （构造 + 归一化 + 入库），评分/策略才能引用——研究已证明单因子方向正确，但组合层需
   作为独立/regime 分量验证，不混入 flip_wide（#178）。
3. **每层都要能独立检验**：行情对账（quote 完整性）→ 因子 IC → 信号命中收益 → 评分分位
   IR → 策略组合 IR/回撤/换手。数据资产新鲜度（data_asset_status）已经逐层在记，策略层要
   沿用同一模式记"策略新鲜度"（上次产组合的时间/评分版本）。
4. **研究链与生产链共用配置与口径**：candidate.yaml（方向/权重/selection）直接成为生产
   策略配置的输入；回测统一走 autoresearch 的快照口径（T+1、无前视、friction、等权基准），
   避免两套回测结论打架。

### 4.4 落地顺序建议（与 H20 结论衔接）

1. **评分构造层版本化**：让生产 scoring 支持"按 model_version 声明分量方向/权重/是否含
   flip"（flip_wide 语义的先决条件）。这是把研究候选变成可跑生产分数的桥。
2. **快照导出器 + 因子层接入估值列**（stock_daily_basic → 因子产物），研究链继续验证
   regime 门控版估值。
3. **策略 runner（最小闭环）**：每日读评分 → 按配置选 top-N 宽书 → 输出目标组合/调仓
   清单 + 新鲜度记录。先 paper 运行（只记录不交易）积累 T+1 证据，≥120 天后才谈真实执行。
4. **统一回测口径**：生产策略验证全部走 T+1 快照口径，废弃/对齐 backend 旧回测。

## 五、结论

- 五层是**单向压缩流水线**：行情(事实) → 因子(特征) → 信号(事件) → 评分(排序) → 策略(组合)。
  每层可独立检验，方向语义只在评分构造层定义。
- 当前最大的结构性缺口是**评分→策略之间没有生产产物**，且**评分方向与数据基建脱节**
  （研究已证明方向需构造层翻转、估值数据已入库但未成因子）。
- 策略层最小实现 = "读生产评分 + 可配置方向/权重/selection/约束 → 每日目标组合与调仓
  清单"，先 paper 后实盘；H20 的 flip_wide 与"宽书优于窄书"应直接编码进默认策略配置。
