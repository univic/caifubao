# 五万元 point-in-time 模拟：2026-08-01 → 2026-09-11（research）

> Research-only。本文记录一次严格限定「只用到评估日为止的信息」的纸面模拟：
> 假设 2026-08-01（周六，首个交易日 08-03）账户有 **50,000 CNY**，用**现有模型**
> 逐期决策，到 **2026-09-11** 的账户价值。不下任何真实订单，不构成投资建议。
>
> 执行环境：`caifubao-research`（image `sha-c2dd5b34`，perf C1 批量化后），
> 数据库 `caifubao-research`。所有决策只读 `date <= D` 的行；实现窗口内的价格
> 只用于估值，从不参与选择。

---

## 1. 结论（先看这一段）

50,000 CNY，5 个交易日一次的调仓节奏（与配置的 `rebalance.cadence_days=5` 一致，
决策日 08-03/08-10/08-17/08-24/08-31/09-07，T+1 开盘成交），到 2026-09-11：

| 变体 | 模型（构造） | 评分模式 | 09-11 账户价值 | 总收益 | 10 个目标中实际成交 | 期末现金 |
|---|---|---:|---:|---:|---:|---:|
| **A 生产现状** | `pit_baseline_h20_v1`（内置生产权重，无翻转） | raw | **45,476.82** | **−9.05%** | 10 | 5,169.82 |
| **B flip 候选** | `pit_flip_ranked_h20_v1`（7 分量 direction −1） | ranked | **50,164.71** | **+0.33%** | 7 | 22,187.71 |
| C ranked 对照 | `pit_baseline_ranked_h20_v1`（排序构造，无翻转） | ranked | **45,603.76** | **−8.79%** | 10 | 7,801.76 |

同期基准：

* 全市场可交易等权（`_benchmark_returns_for_dates` 口径）**+5.80%**
* 沪深 300（sh000300）4,600.93 → 4,510.15 = **−1.97%**

读法：

1. **按现有生产模型（A）的决策方式，5 万会亏到 45,477（−9.05%）**，比等权市场差
   ~14.9pp、比沪深 300 差 ~7.1pp。这与研究结论一致：7 个正向分量在 A 股
   「选高买入」是系统性反预测的。
2. **B（flip 候选）≈ 打平（+0.33%）**：−5.5pp vs 等权，但 **+2.3pp vs 沪深 300**。
   注意它期末有 **44% 现金**（10 个目标里只有 7 个买得起整手），所以它的收益是在
   半仓上取得的。
3. **C 说明「翻转」而不是「排序构造」才是关键**：只换成横截面排序构造（C）几乎和
   生产现状一样亏（−8.79% vs −9.05%）。

## 2. 方法与「无未来信息」纪律

* **决策**：`scoring_runner backfill --from D --to D --horizon 20` 重算当日分数。
  评分引擎的输入**按构造**有界：历史行情 `date < D`、当日 quote/factor/signal
  `date == D`、信号衰减窗 `< D`、行业指标 `date__lt D`、CSI300 到 `D` 为止
  （contract-reviewer 逐条核对过，见 PR #227 的 look-ahead 审计表）。
* **成交**：`strategy_runner run --date D` 读 D 的分数选 10 只，`execution_date` =
  D 之后的第一个交易日，按执行日**开盘价**成交（`paper_causal_v1`），整手（100 股）、
  含佣金/印花税、ST/北交所/停牌剔除。
* **估值**：`strategy_runner nav` 按**原始收盘价**逐执行日标记；本文额外把最后一笔
  持仓用 **09-11 收盘价**重估（`pit_value.py`，回放引擎自己的成交明细拿到精确股数与
  现金），因此终值口径是 09-11，而不是引擎默认的最后执行日 09-08。
* **禁止未来信息**：选股只用 D 及之前；09-11 的价格只用于估值；没有用任何 D 之后的
  收益去挑标的。所选配置对三个变体**完全一致**，唯一差别是 `score_model_version`
  （因此 config_hash 不同、互不干扰）。

三变体的划分动机：生产默认是 **raw**（加权和），而研究候选是「横截面排序 + 方向翻转」。
把「排序构造」单独提出来做 C，才能把 B 的收益拆成「排序」与「翻转」两部分。

## 3. 数据适用性审计（这次模拟最重要的限制）

生产只在窗口的 **11/30 个交易日**真正跑过评分（08-26/27/28/31、09-02…09-11）；
其余日期本次是**重新推导**的。重新推导是否等价于「当时会做的决策」，用同日已存分数
对比来量化（`pit_drift_check.py`，scratch 版本配置与内置生产配置等价）：

| 日期 | 生产行数 | 重推行数 | score 不同 | rank 不同 | 该日生产分数的产出时点 |
|---|---:|---:|---:|---:|---|
| 2026-08-26 | 5,550 | 5,562 | **3,586 (65%)** | 5,209 | **FQ 重写之前** |
| 2026-08-27 | 5,550 | 5,562 | **3,889 (70%)** | 5,036 | **FQ 重写之前** |
| 2026-08-28 | 5,551 | 5,562 | 1 (0.02%) | 2 | 重写之后 |
| 2026-09-11 | 5,562 | 5,562 | **0** | 0 | 重写之后 |

关键事实：`datahub_job_runs` 显示 **2026-08-27 12:39 的 `datahub_quote_stock_daily`
一次性写入 9,619,954 行**（FQ 因子修复后的全历史重算）。因此：

* **08-26 / 08-27 的生产分数是用重写前的数据算的**；用今天的数据重推，65–70% 的
  个股分数不同 → **08-03…08-26 的决策不是「当时的复演」，而是在修正后数据上的反事实**。
* **重写之后的日期（08-28、09-11）重推几乎逐位一致（0–1/5,55x）** → 重新推导流程本身
  是可信的，`pit_baseline_h20_v1` 与生产配置等价。
* 因此只有**两个决策日（08-31、09-07）**落在「未被后续改写」的数据上。它们的干净
  子区间（09-01 → 09-11）：

  | 变体 | 09-01 | 09-11 | 该子区间收益 | 对比 |
  |---|---:|---:|---:|---|
  | A 生产现状 | 46,688.59 | 45,476.82 | **−2.60%** | 等权 −2.93%、沪深300 −2.20% |
  | B flip | 51,311.99 | 50,164.71 | **−2.24%** | |
  | C ranked 对照 | 50,327.36 | 45,603.76 | **−9.39%** | |

  即：在**唯一可称为严格复演**的两期上，生产模型基本上跟着市场走（略好于等权），
  而 flip 候选略好于沪深 300 但不如等权；C 明显更差。样本只有 2 期，不构成统计证据。

## 5. 局限与残余风险（必须与结论一起读）

1. **前 4 个决策日是反事实**：08-03…08-26 的分数是在 2026-08-27 FQ 全历史重写之后的
   数据上重推的（第 3 节）。生产当时**根本没有做过这些决策**。只有 08-31、09-07 两期
   是严格复演。
2. **`industry_daily_metrics` 在 research 库为空**：`industry_momentum` 分量对所有个股
   都返回中性 0.5，无法区分个股（权重 5/100）。这与当时管道一致，但该分量在本模拟中
   是惰性的。
3. **5 万 + 10 只等权在整手约束下买不满**：B 期末 44% 现金（目标里 7/10 可成交），
   A/C 也各有 10–16% 现金。收益是在部分建仓的账面上取得的；换更小的 book 或更大的
   本金结论会不同。
4. **NAV 用原始收盘价**，不含分红/拆股调整（引擎既有约定）；paper 模式无冲击成本、
   无滑点以外的市场影响。
5. **同库并发写入**：调查期间有另一个会话在往同一 research 库写
   `flip_wide_shadow_v1` 的 paper run（日频、不同 config_hash）。本文所有数字都按
   **自己的 config_hash** 过滤，未混入对方记录。
6. **样本极小**：6 期调仓、30 个交易日，任何结论都不具统计意义，只是「现有模型在
   这段时间会怎么做」的一次可复现演算。
7. **`cadence_days` 不被引擎强制**：5 日节奏是靠「只在 6 个决策日建 run」实现的
   （引擎按已有 run 的执行日排程）。

## 6. 运营发现（顺带，非本模拟结论）

1. **`config["directions"]` 只在 ranked 路径生效**：`score_all_stocks`（raw）完全忽略
   directions，因此一个「翻转」模型版本在 `DATAHUB_SCORING_MODE=raw`（dev/research/prod
   当前默认）下会**静默产出与基准完全相同的分数**。本次第一次跑 B 时就撞上了
   （A、B 净值逐分相同）。`_resolve_model_version` 只校验注册与 horizon，不校验模式。
   若要生产化 flip 类模型，必须同时锁定 `scoring_mode`。
2. **research 库原本没有注册模型版本**：本次为模拟注册了
   `pit_baseline_h20_v1` / `pit_baseline_ranked_h20_v1`（`{"20": {}}`，等价内置配置）
   与 `pit_flip_ranked_h20_v1`（flip 配置）。`config_hash` 分别为 `c44ed5c0…`
   （两个 baseline 相同）、`8c8f3ee4…`（与 dev 文档一致；配置内容相同但版本名不同）。
4. **共享 research 库里的 `flip_wide_shadow_v1` 正在被另一会话以 raw 模式写入**：
   检查该版本的 `input_snapshot.scoring_mode` 可见 08-03…09-10 全是 `raw`、只有
   09-07 是 `ranked`（即只有本次运行的那一天）——因为 raw 路径忽略 directions，
   那些行实际上是**未翻转**的基准分数，而另一会话的 paper run 正建立在它们之上。
   这也是本次一开始 B 与 A 净值完全相同的原因。为避免共享键互相覆盖，B 改用**专用**
   版本 `pit_flip_ranked_h20_v1`；用该版本重跑得到与前一次完全相同的终值
   （51,128.71 @09-08），因此本文 B 的数字可复现。
3. **重放/回填路径的评分内存**：单份全市场窗口实测 ~1.06GiB（见
   `docs/operations/perf-analysis-2026-08.md` C1 行），dev datahub 1Gi limit 会被
   OOMKill，已临时提到 2Gi（private#81），根治方案记为 tasks 3.1b。

## 7. 复现命令

```bash
# 0) 模型版本注册（research 库）
python -m app.jobs.model_registry_runner register --model-version pit_baseline_h20_v1 \
  --description "PIT sim baseline (built-in config)" --config-json '{"20": {}}'
python -m app.jobs.model_registry_runner register --model-version pit_baseline_ranked_h20_v1 \
  --description "PIT sim ranked control" --config-json '{"20": {}}'
python -m app.jobs.model_registry_runner register --model-version pit_flip_ranked_h20_v1 \
  --description "PIT sim flip candidate (ranked)" \
  --config-json "$(cat datahub/research/autoresearch/h20_excess_alpha/flip_wide_registry_config.json)"

# 1) 每个决策日：重算分数（T 日）+ 生成目标组合（T+1 开盘执行）
#    flip 变体必须带 DATAHUB_SCORING_MODE=ranked
python -m app.jobs.scoring_runner backfill --from D --to D --horizon 20 \
  --model-version <MV> --replace
python -m app.jobs.strategy_runner run --date D --replace --config-json '<见 pit_sim.py>'

# 2) 净值曲线 + 09-11 估值
python -m app.jobs.strategy_runner nav --from 2026-08-01 --to 2026-09-11 --config-json '<同上>'
```

脚本：`datahub/research/pit_sim/pit_sim.py`（三变体全流程）、
`pit_drift_check.py`（再推导漂移审计）、`pit_value.py`（09-11 精确估值）。
