## 2. 面板与标签的定义（与既有 harness 的差异）

`datahub/app/lib/factor_lab/panel.py`：

* **标签是交易日偏移**：T+1 开盘进场 → 第 h 个交易日的开盘出场（h=1/5/20/60），
  **不用日历窗**。既有 `int(h*1.5)` 日历规则连「周五观测的 h=1」都解析不出来（需要
  3 个日历日），对短线研究是致命的。
* **board-aware 涨跌停**：主板 ±10%、创业板/科创 ±20%、北交所 ±30%、ST ±5%
  （既有 harness 与 `backtest_service._can_trade` 都写死 ±9.9%，对 20% 板会误判）。
  无 `change_rate`（数据缺口）视为不可交易 —— 否则可能买在涨停。
* **不可交易就丢弃（不滚动）**：`blocked_h{h}` 记录原因（`limit_up_entry`/
  `suspended_entry`/`limit_down_exit`/`no_exit_yet`/…）。paper/回测路径是「滚到下一个
  可成交日」，那回答的是「策略会怎么做」并且会**悄悄改变持有期**，两者不能共用标签。
* **净成本口径**：滑点 10bp/边 + 佣金 2.5bp/边 + 卖出印花 10bp = **单次往返 0.35%**，
  与 `autoresearch/profile.yaml` 一致；分位收益直接扣掉它（最低佣金与整手是组合层
  效应，不在标签层）。
* **因子**：`factors.py` 的 17 个向量化实现，全部只用回溯窗口（`shift(k>0)`、trailing
  `rolling`），有单测用「篡改未来一行、过去值必须不变」逐个验证。

## 3. 短线结果（h1 / h5，净成本）

按走查衰减闸门（|IC| train→val/test 衰减 ≤ 0.2）过滤后**通过**的：

| 因子（方向） | h1 IC | h5 IC | h1/h5 衰减 | h1 净多空价差 | h5 净多空价差 |
|---|---:|---:|---:|---:|---:|
| `volatility_20`（做多低波） | **−0.0528** | **−0.0666** | 0.18 / 0.16 | +0.37% | +0.55% |
| `reversal_1`（做多昨日跌） | **+0.0243** | +0.0128 | 0.08 / −0.05 | +0.25% | +0.31% |
| `gap_1`（做多低开） | **+0.0156** | +0.0170 | −0.47 / −0.40 | +0.10% | +0.25% |
| `amihud_20`（做多非流动） | +0.0237 | +0.0496 | **−0.00** / 0.26 | +0.07% | +0.45% |
| `volume_zscore_60`（做空放量） | −0.0548 | −0.0607 | 0.20 / 0.35 | +0.46% | +0.89% |
| `momentum_60`（做空强动量） | −0.0452 | −0.0675 | 0.16 / 0.31 | +0.39% | +0.85% |

**未通过**的多为 `performance_decay`：`momentum_3/10/20`、`reversal_5/10`、`trend_20/60`、
`rsi_14`、`range_position_20`、`volume_ratio_20`、`volatility_60` —— 即**信号在
train 段强、之后衰减**。这正是路线图要求的「decay ≤ 0.2」闸门在起作用。

## 4. 读法（三条可执行的结论）

1. **短线（h1）的成本门槛非常高**：信号价差普遍只有 0.1–0.5%/期，而往返成本 0.35%，
   扣完只剩 `volume_zscore_60` 反向（+0.46%）、`volatility_20` 反向（+0.37%）、
   `reversal_1`（+0.25%）还有余量。**h1 不是没有信号，是信号不够付手续费。**
2. **h5 的可操作性明显好于 h1**：多空价差 0.25–0.9%，同样成本下留出的余量是 h1 的
   2–3 倍，且 `volatility_20`（低波）在 h1/h5 都过衰减闸门 —— 目前最稳的短线候选。
3. **动量族在短端也是反向的**（h1 的 `momentum_20` IC −0.053），说明「反向」不是
   20 日持有的特例，但**强度随 lookback 增加**（`momentum_3` −0.029 → `trend_60` −0.099），
   最好用的仍是中长回看的反转，而不是「昨天跌了就买」。

## 5. 局限（必须与结论一起读）

1. **样本只有 2024–2026（约 630 个交易日）**，覆盖一种 regime；审计里的 8-regime
   结论尚未在本实验室复现（面板可重导 2019 年起）。
2. **未做多重检验校正**：本次跑了 17 因子 × 3 horizon = 51 次检验，5% 阈值下 Bonferroni
   约需 |t| ≥ 3.3。`volatility_20`（|t| 5.8–7.3）、`volume_zscore_60`（|t| 10–15）、
   `momentum_*`（|t| 4.4–10）能过，但 `gap_1`（|t| 4.1）与 `reversal_1`（|t| 4.0）只是
   勉强；**下一片必须先预注册假设再做校正**。
3. **没有控制 size / 行业**：低波与反转在小盘上更明显，而 A 股的 size 效应随 regime
   摆动（审计结论），因此「低波有效」可能部分是 size 代理。需加 size/行业中性化。
4. **未控制流动性下限**：多空价差里可能包含无法成交的微盘股；`amihud_20` 正向尤其可疑
   （非流动 = 难成交）。需叠加 `MIN_LIQUIDITY_CNY` 与成交量占比约束重跑。
5. **ST 过滤失效**（`isST` 自 2026 年起在行情表缺失，根因是 baostock→tushare 数据源
   切换）：面板没有 ST 标记，退市/ST 名可能进入分位统计。
6. **IC 是净成本但非净冲击**：面板口径为「标签减往返成本」，未含市场冲击、涨跌停排队、
   整手约束。
7. 因子目前只用价量（`stock_daily_basic` 的估值/规模尚未并入；`industry_daily_metrics`
   仍为空）。

## 6. 复现

```bash
# 面板（只读 Mongo，写一个 parquet；按代码分块，峰值内存 ~1 块）
python -m app.jobs.factor_lab_runner export --from-date 2024-01-01 --to-date 2026-09-11 \
  --horizons 1,5,20,60 --output /tmp/lab.parquet

# 单因子 / 全因子
python -m app.jobs.factor_lab_runner list
python -m app.jobs.factor_lab_runner evaluate --panel /tmp/lab.parquet \
  --factor momentum_10 --horizons 5,20,60
python -m app.jobs.factor_lab_runner evaluate --panel /tmp/lab.parquet \
  --all --horizons 20 --output /tmp/lab_h20.json
```

实测：面板 3,334,045 行 / 5,561 只 / 261MB parquet；h20 全因子评估在 2Gi pod 内完成
（初版会 OOMKilled，已改为「float32 载入 + 每 horizon 4 列视图 + 不复制整面板」）。
