# Strategy Program P0–P4 — 统一策略定义、研究流水线与双袖资金结构

> 状态：**提案（proposal）**。本文是评审用方案，不含实现。规范性来源是
> [`openspec/changes/strategy-program-2026/`](../../openspec/changes/strategy-program-2026/proposal.md)
> 及其 delta specs；本文与 spec 冲突时以 spec 为准。
>
> 对外定位不变：**research / learning / demonstration MVP，非投资建议**。本方案
> 不授权真实资金执行，也不构成任何投资建议。`prod`（trading/production）仍未启用。

## 1. 为什么需要这个方案

现有策略体系已经具备三件稀缺资产：**可哈希的 StrategySpec**、**域内独立的账本契约**、
**fail-closed 的前瞻证据门禁**。但它缺三样东西，且三者互相纠缠：

1. **声明与行为脱节**。`rebalance.cadence_days` 校验通过、进入 spec hash、写进文档，
   但**没有任何代码消费它**——名义周频、实际日频。`risk.*` 六个字段同样全部定义并
   校验，但每日链路一个都不消费。这种缺陷比功能缺失更危险：它让 spec 在语义上撒谎。
2. **决策逻辑有多个副本**。research 与 future trading 各写一套模拟器，靠
   `GOLDEN_EXECUTION_V1`（仅 3 条费用向量）对齐。费用算术能对齐，选股与组合构建对齐不了。
3. **研究没有统一的验证流程**。同一个 idea 可以从任一处发起，用不同的标签口径、不同的
   基准、不同的窗口跑出不同的数字；`small-book` 研究线上出现过方向搞反（−27.9% vs
   +1.9%，差 30pp）与四次结果作废，根源都是流程缺失而不是算力不足。

因此本方案的顺序是：**先把语义地基做对（P0/P1），再把验证流程固化（P2），
最后才让资金结构去使用它（P3/P4）**。顺序反了就是重复现有问题。

## 2. 已定决策

| 决策 | 内容 | 影响 |
|:---|:---|:---|
| D1 | 稳健半仓改为 **ETF 多资产配置**，不再改造 flip 个股簿 | P3 重新定义载体；flip 退出稳健角色 |
| D2 | flip 簿**维持现有窗口**（`01c196b8…`）继续运行 | 不关窗、不改 spec；其证据仍按原样积累 |
| D3 | 激进袖独立核算、独立门禁 | P4 与 P3 资金与风险隔离 |

D2 的代价必须写明：该窗口会计口径仍是 UNVERIFIED（分红/送转未入账），因此它跑出的
结果**不能用于验收**，只能作为观察。这不影响 D2，但必须在结论里标注。

## 3. 一致性的核心契约

「规则 / 机器学习 / 大模型」在**信号层**不同，在**决策层与执行层**必须完全相同。
唯一能保证这一点的结构是：**一份决策实现 + 三个执行端点**。

```text
                    ┌──────────────────────────┐
  spec ────────────►│  SignalProvider          │  rule / ml / llm
  snapshot ────────►│  (date,stock)→score      │  ← 唯一允许分叉的地方
                    └────────────┬─────────────┘
                                 ▼
                    ┌──────────────────────────┐
                    │  decide()  纯函数         │  ← 唯一实现，四模式共用
                    │  → TargetBook + Reasons  │
                    └────────────┬─────────────┘
                                 ▼
                    ┌──────────────────────────┐
                    │  RiskGate  纯函数         │  ← 唯一实现，四模式共用
                    └────────────┬─────────────┘
                                 ▼
        ┌────────────────┬───────┴────────┬────────────────┐
        ▼                ▼                ▼                ▼
   BACKTEST         RESEARCH_SIM      TRADING_PAPER       LIVE
   (历史快照)        (当日快照)         (模拟撮合)         (券商)
        └────────────────┴────────────────┴────────────────┘
                    只有 Executor 与 Ledger 不同
```

四条可测的一致性不变量：

| # | 不变量 | 验证方式 |
|:---:|:---|:---|
| I1 | 同 spec + 同快照 + 同 session + 同工件 → 目标组合 bit-identical | 跨模式 golden TargetBook 对拍 |
| I2 | 大模型类：同 spec + 同快照 + 同 session + **同已记录响应** → 同目标组合 | 记录-重放回归测试 |
| I3 | 模式只能改变成交结果，永不改变目标组合 | 同输入跑四模式，diff 目标组合必须为空 |
| I4 | 所有模式写同一个 `TargetBook` schema | schema 校验 |

I2 是新增的，因为**大模型的输出不可复现**。对 AI 类策略，「行为一致」的正确含义不是
「确定性」，而是「**可审计重放**」：把 prompt、模型标识、响应与其哈希一次性录制，
之后任何重跑都读缓存而不重新调用。换提示词或换模型 = 新工件 = 新 spec hash。

## 4. 阶段概览

| 阶段 | 目标 | 主要交付 | 依赖 | 阻断性 |
|:---|:---|:---|:---|:---|
| **P0** | 声明即行为：字段有消费者、出场显式、结构门禁 | `strategy-spec-completeness` | — | 🔴 后续全部 |
| **P1** | 三类信号源统一接入，AI 只出分不出单 | `strategy-signal-providers` | P0 | 🔴 P3/P4 |
| **P2** | 预注册 + 试验计数 + 六阶段 verdict | `strategy-research-pipeline` | P0（弱依赖 P1） | 🔴 P4 |
| **P3** | ETF 多资产稳健半仓，可承载半数资金 | `stable-multi-asset-sleeve` | P0/P1 | — |
| **P4** | 激进袖：60 日框架 + 新信息集 + LLM 二次筛选 | `aggressive-sleeve-research` | P0/P1/P2 | — |

### P0 — 策略声明的完备性

**问题**：spec 能声明不生效的字段；出场语义靠排名隐含；没有止损；无法表达快照与模型
绑定；`universe` 是等值断言（`!= {"market":"CN_A","as_of":"PIT"}` 直接抛错），连 ETF
都装不进去。

**交付**：

- `spec_version: "2"`：新增 `identity`（假设/预期特征/替代关系）、`data.snapshot_id`、
  `signal.model_config_hash`、`signal.score_basis`、显式 `selection.exit`
  （`rank_below` / `stop_loss_pct` / `max_hold_sessions` / `on_ineligible`）、
  `accounting`（公司行动口径）、`benchmark`、`evidence.kill_criteria`。
- **consumption manifest**：`openspec/specs/strategy-declaration/consumers.yaml` 记录
  每个字段路径 → 消费模块 + golden 测试。CI 校验「声明字段必有消费者」。
- **结构门禁**：校验阶段拒绝注定失败的配置（最小持仓数、年换手预算、集中簿必须有止损、
  回撤预算）。当前 spec 能执行「5 只票 + 无止损 + 无换手预算」，这本身就是缺陷。
- **v1 兼容**：`spec_version: "1"` 保持可读、可重放、可归档，但**不得开新窗口**。

**验收**：v1 已认证窗口 `01c196b8…` 的 `spec_hash` 不变；v2 spec 通过结构门禁；
manifest 覆盖率 100%（无未消费字段）；`openspec validate --all --strict` 通过。

### P1 — 统一信号源

**交付**：`SignalProvider` 契约 + 三个实现（`RuleScoreProvider` / `MLModelProvider` /
`LLMProvider`），全部输出同一 schema `(date, stock, score, percentile, rationale)`。

三条硬规则：

1. **AI 只出分，不出单**。仓位由 spec 决定，风控由 RiskGate 决定。provider 不得输出
   `side` / `quantity` / `weight`。
2. **LLM 只在候选池上做二次筛选**。全市场 5,000 只 × 244 日 ≈ 127 万次调用/年，按大
   模型价格相当于 50 万本金的 2%–26%，直接吃光收益。正解是先用规则/ML 筛到 200 只。
3. **推理成本进会计**。LLM/ML 推理成本是一种真实成本，必须与佣金并列记账；否则所有
   AI 策略回测都会系统性高估收益。

**验收**：同一 spec 在三类 provider 下产出同 schema 的 TargetBook；记录-重放测试通过
（第二次运行零外部调用）；provider 越权字段被 schema 拒绝。

### P2 — 研究流水线

**交付**：六阶段流水线 + 三个机制。

| 阶段 | 门禁 | 允许产出结论 |
|:---|:---|:---|
| S0 预注册 | 假设/数据/判据/**试验次数上限**先行登记 | — |
| S1 数据可行性 | 数据存在、PIT 安全、历史够长 | — |
| S2 探索 | 每评估一个配置，计数器 +1 | ❌ 只出情报 |
| S3 确认 | 只能测预注册配置、只测一次、rolling + purge + embargo | ✅ 研究结论 |
| S4 结构与容量 | 分散度/换手预算/回撤预算/必须有止损/**资金×10 再跑一遍** | — |
| S5 前瞻 | 120 个交易日窗口 | ✅ 晋级候选 |
| S6 判定 | 不可变 `verdict.json`，引用 spec hash/试验数/快照/代码 SHA | — |

**三个机制**：预注册（禁止事后改判据）、试验计数器（多重检验校正，仓库已有
Bonferroni 工具）、结构+容量门禁（让流程而不是人事后读表来拒绝坏配置）。

**验收**：一个 idea = 一个 YAML + 一条命令；无预注册的评估无法生成结论；verdict 可追溯
到试验次数与代码 SHA。

### P3 — 稳健半仓（ETF 多资产）

**问题**：当前 flip 簿**在结构上不能承担稳健半仓**。三条算术约束无法调参解决：

| 约束 | 算术 | 结论 |
|:---|:---|:---|
| 宽度不可达 | edge 只在 800 只宽度为正；10 万 × 5,000 元/只 = 20 只；800 只约需 400 万 | 10 万本金取不到该信号赖以生存的宽度 |
| 换手与成本 | 日频重排 → 年换手 ~139 → 摩擦 42%/年 | 稳健配置需年换手 < 4（摩擦 ~1%） |
| 尾部风险 | 无止损 + 越跌分越高 → 回撤由构造决定（N=20 实测 −68%） | 中等风险预算为 15%–20% |

**关键洞察：小资金要吃「宽度」，只能靠 ETF，不能靠个股。** 个股宽度是本金买出来的，
ETF 宽度是产品自带的——5 万即可获得 300 只股票的分散度。这也解释了为什么仓库唯一有
正面证据的可行配置是多资产，而不是选股。

**交付**：`stable-multi-asset-sleeve` spec + 目标画像（年化 8%–12%、回撤预算
15%–20%、年换手 ≤ 4、基准 = 静态 60/40 或 25/25/25/25）。

**必须写进 spec 的诚实边界**：静态 25/25/25/25 的 +10.8% 报告自己声明「超额来自美股与
黄金的强势，是**事后可知的资产选择**」——换成恒生掉到 +7.7%/Sharpe 0.60/5 个负年。
因此稳健的部分不是「持有这四个资产」，而是「**低相关资产 + 波动目标 + 定期再平衡**」
这条规则；资产集必须**预先固定**，禁止事后替换。

### P4 — 激进袖

**已被仓库数据否掉的**：20 日技术面趋势/主升浪识别。8 个技术分量在 2019–2026 全部
regime 显著负 IC，反转后才转正；「买最强动量」在 N=30 实测 **−27.9%**。

**真实开口**：仓库自己的持有期扫描里，**h60 + 出口带 2.0 是全表最好的一行**——年化超额
+35.2%、超额回撤 −11.4%、年换手仅 2.25。短周期是反转有效、趋势无效；长周期恰恰反过来。
所以「主升浪」的正确 horizon 是 **60 日，不是 20 日**。代价：利润集中度 0.25（1/4 超额
来自单一时期），且与滚动 OOS 口径未对齐——它是**待验证的开口，不是结论**。

**ML 与 LLM 的分工**：

| 用途 | 判断 |
|:---|:---|
| 同样 8 个价量特征上找非线性 | ❌ 低预期，线性组合已是负 IC，非线性救不了信息量 |
| regime 分类 / 仓位管理 | ✅ 有价值，但影响仓位不影响选股 |
| **引入新信息集**（公告/业绩预告/龙虎榜/新闻） | ✅ **最高预期** |
| 让模型「看图识主升浪」 | ❌ 不可验证、不可复现、成本高 |

**交付**：60 日框架 + 事件数据源落地（走 datahub `fetch→normalize→validate→publish`）
+ LLM 二次筛选（≤200 只/日，成本入账）+ 风险隔离（激进袖亏损不得侵蚀稳健袖）。

## 5. 不做什么（Non-goals）

- 不实现真实券商执行、不启用 `trading-paper`/`prod`、不授权真实资金。
- 不改变已认证窗口 `01c196b8…` 的任何字节（D2）。
- 不把 v1 窗口升级为 v2 证据；语义变化 = 新窗口。
- 不在 P4 之前扩大激进袖资金。
- 不为 ML/LLM 单独造一套风控或账本——它们必须复用同一 RiskGate 与同一决策函数。
- 不承诺「快速翻倍」。本方案的目标是**让每个想法在两周内得到是/否结论**，而不是让回测
  曲线好看。

## 6. 风险与缓解

| 风险 | 缓解 |
|:---|:---|
| P0 改动触碰已认证窗口 | v1 只读保留；`spec_hash` 回归测试钉住 `01c196b8…` |
| consumption manifest 变成官僚负担 | 只要求「字段 → 消费者 + golden」，不要求文档 |
| LLM 不确定性污染证据 | 强制记录-重放；未录制响应的运行不得计入证据 |
| 多阶段一次做大 | 每阶段独立 PR、独立验收；P0 未过不复核 P1 |
| 研究流水线拖慢探索 | S2 明确允许任意扫描，只要求计数，不要求预注册 |
| 稳健袖资产选择事后挑 | spec 预固定资产集；替换资产 = 新 spec = 新证据 |

## 7. 里程碑

| 里程碑 | 完成标志 |
|:---|:---|
| M0 | P0 spec 通过评审并合入；manifest 覆盖率 100% |
| M1 | P1 provider 契约落地；记录-重放测试通过 |
| M2 | P2 流水线可用；第一个 idea 走完全流程 |
| M3 | P3 稳健袖跑满 120 日前瞻窗口且无 FAIL |
| M4 | P4 激进袖完成首轮事件数据回测并出 verdict |

M3 之前，**任何「半数资金、稳健中等风险」的对外表述都不成立**。
