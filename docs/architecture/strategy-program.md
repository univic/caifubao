# Strategy Program P0–P4 — 统一策略定义、研究流水线与双袖资金结构

> 状态：**提案（proposal）**。本文是评审用方案，不含实现。规范性来源是
> [`openspec/changes/strategy-program-2026/`](../../openspec/changes/strategy-program-2026/proposal.md)
> 及其 delta specs；本文与 spec 冲突时以 spec 为准。
>
> 对外定位不变：**research / learning / demonstration MVP，非投资建议**。本方案
> 不授权真实资金执行，也不构成任何投资建议。`prod`（trading/production）仍未启用。

## 1. 为什么需要这个方案

现有策略体系已经具备三件稀缺资产：**可哈希的 StrategySpec**、**域内独立的账本契约**、
**fail-closed 的前瞻证据门禁**。但它缺三样东西，且三者互相纠缠：

1. **声明与行为脱节**。`rebalance.cadence_days` 校验通过、进入 spec hash、写进文档，
   但**没有任何代码消费它**——名义周频、实际日频。`risk.*` 六个字段同样全部定义并
   校验，但每日链路一个都不消费。这种缺陷比功能缺失更危险：它让 spec 在语义上撒谎。
2. **决策逻辑有多个副本**。research 与 future trading 各写一套模拟器，靠
   `GOLDEN_EXECUTION_V1`（仅 3 条费用向量）对齐。费用算术能对齐，选股与组合构建对齐不了。
3. **研究没有统一的验证流程**。同一个 idea 可以从任一处发起，用不同的标签口径、不同的
   基准、不同的窗口跑出不同的数字；`small-book` 研究线上出现过方向搞反（−27.9% vs
   +1.9%，差 30pp）与四次结果作废，根源都是流程缺失而不是算力不足。

因此本方案的顺序是：**先把语义地基做对（P0/P1），再把验证流程固化（P2），
最后才让资金结构去使用它（P3/P4）**。顺序反了就是重复现有问题。

## 2. 已定决策

| 决策 | 内容 | 影响 |
|:---|:---|:---|
| D1 | 稳健半仓改为 **ETF 多资产配置**，不再改造 flip 个股簿 | P3 重新定义载体；flip 退出稳健角色 |
| D2 | flip 簿**维持现有窗口**（`01c196b8…`）继续运行 | 不关窗、不改 spec；其证据仍按原样积累 |
| D3 | 激进袖独立核算、独立门禁 | P4 与 P3 资金与风险隔离 |

D2 的代价必须写明：该窗口会计口径仍是 UNVERIFIED（分红/送转未入账），因此它跑出的
结果**不能用于验收**，只能作为观察。这不影响 D2，但必须在结论里标注。

## 3. 一致性的核心契约

「规则 / 机器学习 / 大模型」在**信号层**不同，在**决策层与执行层**必须完全相同。
唯一能保证这一点的结构是：**一份决策实现 + 三个执行端点**。

```text
                    ┌──────────────────────────┐
  spec ────────────►│  SignalProvider          │  rule / ml / llm
  snapshot ────────►│  (date,stock)→score      │  ← 唯一允许分叉的地方
                    └────────────┬─────────────┘
                                 ▼
                    ┌──────────────────────────┐
                    │  decide()  纯函数         │  ← 唯一实现，四模式共用
                    │  → TargetBook + Reasons  │
                    └────────────┬─────────────┘
                                 ▼
                    ┌──────────────────────────┐
                    │  RiskGate  纯函数         │  ← 唯一实现，四模式共用
                    └────────────┬─────────────┘
                                 ▼
        ┌────────────────┬───────┴────────┬────────────────┐
        ▼                ▼                ▼                ▼
   BACKTEST         RESEARCH_SIM      TRADING_PAPER       LIVE
   (历史快照)        (当日快照)         (模拟撮合)         (券商)
        └────────────────┴────────────────┴────────────────┘
                    只有 Executor 与 Ledger 不同
```

四条可测的一致性不变量：

| # | 不变量 | 验证方式 |
|:---:|:---|:---|
| I1 | 同 spec + 同快照 + 同 session + 同工件 + **同 `DecisionState`** → 目标组合 bit-identical | 跨模式 golden TargetBook 对拍 |
| I2 | 大模型类：同 spec + 同快照 + 同 session + **同已记录响应** + 同 `DecisionState` → 同目标组合 | 记录-重放回归测试 |
| I3 | 模式只能改变成交结果，永不改变目标组合 | 同输入跑四模式，diff 目标组合必须为空 |
| I4 | 所有模式写同一个 `TargetBook` schema | schema 校验 |

I2 是新增的，因为**大模型的输出不可复现**。对 AI 类策略，「行为一致」的正确含义不是
「确定性」，而是「**可审计重放**」：把 prompt、模型标识、响应与其哈希一次性录制，
之后任何重跑都读缓存而不重新调用。换提示词或换模型 = 新工件 = 新的解析输入。

### 3.1 `DecisionState` 必须是显式输入

「同 spec + 同快照 + 同 session」**不足以**决定目标组合：止损要用成本价、最长持有要用
持有会话数、出口带要用上一版持仓、降险规则要用历史峰值。这些都不在 spec 里，也不在行情
快照里。因此决策函数的签名必须包含 `DecisionState`：

```text
decide(spec, provider_outputs, snapshot, session, decision_state) -> TargetBook
```

`DecisionState` 至少包含：持仓（代码、数量、**平均成本**、开仓日期）、`hold_count`、
`entry_reason`、组合历史峰值、现金、未完成订单。它由账本投影得到，**不得**由执行器临时
推测。

跨模式等价因此必须按「状态链」校验，而不是单日目标组合：

- 同一 `DecisionState` 下四模式的目标组合必须逐字段相同（I1/I3）；
- 从初始状态连续多日推进时，若状态发生分叉，**分叉必须归因到具体的成交差异**
  （executor 的责任），不得归因到决策；
- 因此每次运行除 `TargetBook` 外还必须写出 `decision_state_hash`，使分叉可定位。

### 3.2 身份分层：策略配置、研究数据、每日运行输入

一个固定的 `data.snapshot_id` 无法同时满足「回测可复现」和「前瞻每天用新数据」。因此
**必须区分三个身份**，而不是把所有东西塞进 spec：

| 身份 | 内容 | 何时变化 | 谁负责钉住 |
|:---|:---|:---|:---|
| **策略配置身份** `spec_hash` | 声明本身（含数据*要求*，不含具体快照） | 改声明 | 前瞻窗口、历史证据 |
| **研究数据身份** `dataset_id` | 快照集合 / cohort / 日历版本 | 换数据 | 研究 verdict、回测产物 |
| **每日运行输入身份** `resolved_inputs` | 当日快照 id + 解析后的模型工件 digest + `decision_state_hash` | 每个 session | 每个 run 文档 |

派生：`run_id = hash(spec_hash, resolved_inputs, session)`。

由此得到三条规则：

1. **声明只声明数据要求**（市场/资产类别、日历、时区、PIT 政策、新鲜度与质量门禁），
   **不声明具体快照**。这样前瞻窗口的身份不会被次日的快照更新打破。
2. **回测可复现性由 `dataset_id` 钉住**：一个 verdict 必须同时引用 `spec_hash` 与
   `dataset_id`，否则不可复现。
3. **前瞻证据由 `spec_hash` 钉住**，`resolved_inputs` 每次记录、可审计；每日快照变化
   不改变策略身份，但任何一次运行都能被精确重放。

滚动重训（refit）同理：声明里写 `refit_policy`（冻结或滚动 + 训练窗/purge），**具体
工件 digest 按 session 解析并逐次记录**；注册表必须 append-only，否则历史重放会漂移。


## 4. 阶段概览

| 阶段 | 目标 | 主要交付 | 依赖 | 阻断性 |
|:---|:---|:---|:---|:---|
| **P0** | 声明即行为：字段有消费者、出场显式、结构门禁 | `strategy-spec-completeness` | — | 🔴 后续全部 |
| **P1** | 三类信号源统一接入，AI 只出分不出单 | `strategy-signal-providers` | P0 | 🔴 P3/P4 |
| **P2** | 预注册 + 试验计数 + 六阶段 verdict | `strategy-research-pipeline` | P0（弱依赖 P1） | 🔴 P4 |
| **P3** | ETF 多资产稳健半仓，可承载半数资金 | `stable-multi-asset-sleeve` | P0/P1 | — |
| **P4** | 激进袖：期限显式 + 新信息集 + LLM 二次筛选 | `aggressive-sleeve-research` | P0/P1/P2 | — |

### P0 — 策略声明的完备性

**问题**：spec 能声明不生效的字段；出场语义靠排名隐含；没有止损；`universe` 是等值断言
（`!= {"market":"CN_A","as_of":"PIT"}` 直接抛错），连 ETF 都装不进去；单一出场形状也不
适配资产配置类策略。

**交付**：

- `spec_version: "2"` 的分层字段：`identity`（假设/预期特征/替代关系）、`data`（**数据
  要求**：市场/资产类别、日历、时区、PIT 政策、新鲜度与质量门禁；**不含具体快照**）、
  `signal`（模型引用 + `score_basis` + 冻结或 `refit_policy`）、`accounting`、
  `benchmark`、`evidence.kill_criteria`。
- **策略族显式化**：`family` 至少区分 `rank_selection`（横截面打分 → 排名簿）与
  `asset_allocation`（固定资产集 → 目标权重）。每个族声明**自己**必需的再平衡/出场语义：
  排名簿必须有排名出场与止损语义；配置族必须有目标权重、带宽与（真实消费的）再平衡节奏，
  **不强制排名出场**。两族共享风控、执行、会计与账本契约。
- **consumption manifest**：`openspec/specs/strategy-declaration/consumers.yaml` 记录
  每个字段路径 → 消费模块 + golden 测试。CI 校验「声明字段必有消费者」。
- **结构门禁**：校验阶段拒绝注定失败的配置（最小持仓数、年换手预算、集中簿必须有止损、
  回撤预算）。
- **v1 保留旧执行语义（关键）**：`spec_version: "1"` 不只是「可读可重放」，而是
  **继续以旧语义执行**——`cadence_days` 仍然只校验不消费、`risk.*` 仍不进每日链路。
  实现必须按 `spec_version` 分派语义，**不得**按字段存在与否分派。否则接入新消费者会
  在 hash 完全不变的情况下悄悄改变已认证窗口的决策节奏。

**验收**：不只校验两个 hash。必须包含**连续多日回归**——对 v1 声明跑 N 个连续 session，
改动前后目标组合、订单清单与账本投影逐字段一致；v2 通过结构门禁；manifest 覆盖率 100%
（无未消费字段）；`openspec validate --all --strict` 通过。


### P1 — 统一信号源

**交付**：`SignalProvider` 契约 + 三个实现（`RuleScoreProvider` / `MLModelProvider` /
`LLMProvider`），全部输出同一 schema `(date, stock, score, percentile, rationale)`。

三条硬规则：

1. **AI 只出分，不出单**。仓位由 spec 决定，风控由 RiskGate 决定。provider 不得输出
   `side` / `quantity` / `weight`。
2. **LLM 只在候选池上做二次筛选**。全市场 5,000 只 × 244 日 ≈ 127 万次调用/年，按大
   模型价格相当于 50 万本金的 2%–26%，直接吃光收益。正解是先用规则/ML 筛到 200 只。
3. **推理成本进会计**。LLM/ML 推理成本是一种真实成本，必须与佣金并列记账；否则所有
   AI 策略回测都会系统性高估收益。

**验收**：同一 spec 在三类 provider 下产出同 schema 的 TargetBook；记录-重放测试通过
（第二次运行零外部调用）；provider 越权字段被 schema 拒绝。

### P2 — 研究流水线

**交付**：六阶段流水线 + 三个机制。

| 阶段 | 门禁 | 允许产出结论 |
|:---|:---|:---|
| S0 预注册 | 假设/数据/判据/**试验次数上限**先行登记 | — |
| S1 数据可行性 | 数据存在、PIT 安全、历史够长 | — |
| S2 探索 | 每评估一个配置，计数器 +1 | ❌ 只出情报 |
| S3 确认 | 只能测预注册配置；测试集在探索期不可见；cutoff ≤ 测试起点 − 标签期限 − 1 − embargo；**确认次数 ≤ 声明上限** | ✅ 研究结论 |
| S4 结构与容量 | 分散度/换手预算/回撤预算/必须有止损/**资金×10 再跑一遍** | — |
| S5 前瞻 | 120 个交易日窗口 | ✅ 晋级候选 |
| S6 判定 | 不可变 `verdict.json`，引用 spec hash / dataset id / 试验数 / 代码 SHA | — |

**五个机制**（前三个是原方案，后两个是评审补充的防过拟合要求）：

1. **预注册**：假设、数据、程序、成功判据、失效判据、试验上限在第一次评估前落库。
2. **试验计数器**：每评估一个配置 +1，确认阶段阈值按计数调整（仓库已有 Bonferroni 工具）。
3. **结构 + 容量门禁**：让流程而不是人事后读表来拒绝坏配置。
4. **数据隔离**：确认集在注册时即固定（日期/索引落库），探索期**不可读**其价格与结果；
   标签期限要求的 purge 与 embargo 在 cutoff 上强制，跨过边界即拒绝。
5. **跨注册的试验归属**：试验按**假设族**累计，而不是按 registration 累计。用新
   registration 重置计数器是最容易的过拟合后门，因此同族的新注册必须继承累计试验数，
   确认次数上限也按族计算。

**验收**：一个 idea = 一个 YAML + 一条命令；无预注册的评估无法生成结论；verdict 可追溯
到试验次数、`dataset_id` 与代码 SHA；换 registration 重测会被试验归属拦下。


### P3 — 稳健半仓（ETF 多资产）

**问题**：当前 flip 簿**在结构上不能承担稳健半仓**。三条算术约束无法调参解决：

| 约束 | 算术 | 结论 |
|:---|:---|:---|
| 宽度不可达 | edge 只在 800 只宽度为正；10 万 × 5,000 元/只 = 20 只；800 只约需 400 万 | 10 万本金取不到该信号赖以生存的宽度 |
| 换手与成本 | 日频重排 → 年换手 ~139 → 摩擦 42%/年 | 稳健配置需年换手 < 4（摩擦 ~1%） |
| 尾部风险 | 无止损 + 越跌分越高 → 回撤由构造决定（历史报告记 −68%，**已失效待重算**） | 中等风险预算为 15%–20% |

**关键洞察：小资金要吃「宽度」，只能靠 ETF，不能靠个股。** 个股宽度是本金买出来的，
ETF 宽度是产品自带的——5 万即可获得 300 只股票的分散度。这也解释了为什么仓库唯一有
正面证据的可行配置是多资产，而不是选股。

**交付**：`stable-multi-asset-sleeve` spec + 目标画像（年化 8%–12%、回撤预算
15%–20%、年换手 ≤ 4、基准 = 静态 60/40 或 25/25/25/25）。

**必须写进 spec 的诚实边界**：静态 25/25/25/25 的 +10.8% 报告自己声明「超额来自美股与
黄金的强势，是**事后可知的资产选择**」——换成恒生掉到 +7.7%/Sharpe 0.60/5 个负年。
因此稳健的部分不是「持有这四个资产」，而是「**低相关资产 + 波动目标 + 定期再平衡**」
这条规则；资产集必须**预先固定**，禁止事后替换。

### P4 — 激进袖

**研究方向（保留），但结论尚未成立。** 以下数字来自研究记录，且引用它们的报告已发布失效
声明，**必须视为待重算**，不得作为设计依据：

- 持有期扫描中 h60 + 出口带 2.0 是全表最好的一行（+35.2%、超额回撤 −11.4%、年换手
  2.25）。**该方法用的是五因子合成信号、只改动了持有期与出口带**，与 `flip_wide` 不是
  同一个信号；因此它**不能**被推导成「长周期趋势有效」，更不能推出「正确 horizon 是
  60 日」。它只说明：**期限这个维度值得单独做一次干净的重算**。
- 「8 个技术分量全 regime 负 IC」「买最强动量 −27.9%」来自同一批记录，同样待重算。

因此 P4 的第一件事不是选策略，而是**在真实回放口径下重算这些数字**（P2 流水线的第一个
用例）。在那之前，任何关于「哪个期限正确」「哪种技术有效」的断言都不写进契约。

**待检验的假设（不是结论）**：

| 假设 | 状态 |
|:---|:---|
| 期限（h1/h5/h20/h60）与出口带是独立的收益维度，需分别重算 | 待验证 |
| 非线性模型在同一批价量特征上可能有增量 | **未验证**——现有线性组合在这些特征上没有稳定增量，既不构成支持也不构成否定 |
| 引入新信息集（公告/业绩预告/龙虎榜/新闻）可能提供增量 | 优先级最高，因为它是唯一在**信息面**上的扩展 |
| regime 分类影响仓位而非选股 | 合理但未验证 |
| 让模型直接「看图识主升浪」 | 不可验证、不可复现，**不纳入** |

**交付**：期限维度显式化（声明即评估，禁止跨期限借用结论）+ 事件数据源落地（走 datahub
`fetch→normalize→validate→publish`）+ LLM 二次筛选（≤200 只/日，成本入账）+ 风险隔离
（激进袖亏损不得侵蚀稳健袖）。


## 5. 不做什么（Non-goals）

- 不实现真实券商执行、不启用 `trading-paper`/`prod`、不授权真实资金。
- 不改变已认证窗口 `01c196b8…` 的任何字节（D2）。
- 不把 v1 窗口升级为 v2 证据；语义变化 = 新窗口。
- 不在 P4 之前扩大激进袖资金。
- 不为 ML/LLM 单独造一套风控或账本——它们必须复用同一 RiskGate 与同一决策函数。
- 不承诺「快速翻倍」。本方案的目标是**让每个想法在两周内得到是/否结论**，而不是让回测
  曲线好看。

## 6. 风险与缓解

| 风险 | 缓解 |
|:---|:---|
| P0 改动触碰已认证窗口 | v1 只读保留；`spec_hash` 回归测试钉住 `01c196b8…` |
